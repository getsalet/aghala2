## پایلوت یک مقاله، نه اجرای جمعی

فایل `data/agri-v2/review-pilot-6.json` شش پیشنهاد اولیه P1 را دارد؛ همه هنوز نیازمند پژوهش‌اند. template جای تأیید واقعی نیست:

```sh
python -m automation.agri_v2 brief-template --topic-id agri-XXXXXXXXXXXX --output data/agri-v2/briefs/my-brief.json
```

شناسه واقعی را از ماتریس بردارید. در brief، نام واقعی دبیر/بازبین، تاریخ، بررسی معنایی، طرح مستقل، منابع معتبر همراه بخش/صفحه و گزیده، و حقایق تأییدشده با شرایط/واحد ثبت شود. برای منشأ REVIEW بررسی هم‌پوشانی مستقل الزامی است. تأیید ساختگی یا عدد بدون منبع نگذارید. منابع آموزشی واقعی، نه URL نمونه، لازم‌اند.

موجودی تازه باید شامل `source_generated_at` با timezone و `records` کامل با `id,title,url,status` باشد؛ همه مقاله‌های فارسی مرتبط و وضعیت‌های قابل دسترسی تیم را پوشش دهد. ایندکس ناقص را کامل معرفی نکنید. خطای دریافت، ایندکس خالی یا قدیمی مجوز تولید نیست. تشخیص ماشینی فعلی فقط عنوان نرمال و slug را کنترل می‌کند؛ تشخیص شباهت معنایی باید در بررسی دبیر انجام شود.

```sh
python -m automation.agri_v2 draft \
  --topic-id agri-XXXXXXXXXXXX \
  --brief data/agri-v2/briefs/my-brief.json \
  --inventory path/to/fresh-title-inventory.json \
  --allow-model-calls
```

پرچم آخر صریحاً هزینه فراخوانی مدل را مجاز می‌کند. در Actions، workflow `AFP agri v2 - isolated draft generator`، شاخه همین feature، mode=draft، یک شناسه، مسیر brief و inventory و تأیید هزینه را انتخاب کنید. push فقط تست آفلاین انجام می‌دهد. schedule و ادامه خودکار وجود ندارد. **workflowهای قدیمی ترجمه/SQL/هاست را برای این داده اجرا نکنید.** فایل `article-content-queue.yml` فقط روی این شاخه با مسیر مستقل جایگزین شده؛ main و صف قدیمی تغییر نکرده‌اند.

خروجی زیر `artifacts/agri-v2/new/<id>/` قرار می‌گیرد. متن یک بار stage می‌شود، تصویرهای انجام‌شده در retry دوباره درخواست نمی‌شوند، وضعیت پایان‌یافته بازتولید نمی‌شود. تغییر brief بعد از stage متوقف می‌شود. HTML محدود، لینک‌ها در allowlist منابع و اعداد در مجموعه حقایق تأییدشده کنترل می‌شوند؛ این کنترل لغوی **اثبات صحت علمی یا تطبیق درست هر عدد با ادعای خودش نیست**. بازبینی نهایی علمی و ویرایشی همچنان الزامی است.

سه تصویر AI تصویرسازی‌اند، نه شاهد علمی یا تصویر واقعی مزرعه. payload فعلاً متن و status=draft دارد؛ فایل تصاویر جداست و آپلود، انتخاب featured image و جای‌گذاری رسانه مرحله اتصال بعدی است. ترجمه پنج‌زبان در نسخه حاضر اجرا نمی‌شود؛ ابتدا پایلوت فارسی و حقایق تأییدشده، سپس توسعه ترجمه.

## صف ادغام / توسعه

ابتدا هدف واقعی را از `candidate_target_ids` انتخاب و صفحه را بخوانید. ۵ موضوع QUEUED هنوز هدف شناخته‌شده ندارند و عمداً مسدودند. صرف شباهت عنوان مجوز تغییر مقاله نیست.

snapshot داخلی صفحه هدف: `id,url,modified,fetched_at,content_html,content_sha256`؛ مقدار آخر SHA256 متن HTML دقیق است. آن را با محتوای خصوصی در مخزن عمومی commit نکنید.

```sh
python -m automation.agri_v2 merge-plan \
  --topic-id agri-XXXXXXXXXXXX --target-id 123 \
  --snapshot /private/target-snapshot.json --brief /private/approved-merge-brief.json
```

این فرمان بدون مدل و بدون شبکه فقط پیشنهاد می‌سازد. `group_id=post-<id>` برای کنارهم‌گذاشتن موضوع‌های یک هدف است. توسعه‌دهنده مرحله اعمال باید همه پیشنهادهای یک هدف را یکپارچه کند، نسخه زنده/modified/هش را دوباره کنترل کند، patch کوچک و برگشت‌پذیر بسازد و تأیید جدا بگیرد. هیچ فرمان apply در این نسخه وجود ندارد.

## محدودیت علمی و مشخصات محصول

فقط نوار تیپ بغل‌دوخت AFP با روزنه ۱۰ و ۲۰ سانتی‌متر: **فشار کاری ۰٫۶ تا ۱ اتمسفر (atm)**. atm با bar برابر نیست؛ فشار کاری با تحمل/آزمون برابر نیست و به دیگر مدل‌ها تعمیم داده نشود. شرایط مرجع اندازه‌گیری دبی هنوز تأیید نشده؛ دبی یا طول خط از این عدد ساخته نشود.

عملکرد تر/خشک، هر چین/کل فصل، بذر/نشا/غده و محصول قابل‌فروش تفکیک شوند. نسخه سم/اسید/کود بدون متخصص و شرایط محلی تولید نشود. عدد، منبع، تأیید بازبین یا تضمین سود/برداشت نسازید.

## اتصال‌های مرحله بعد

۱. همین حالا برای آزمایش واقعی فقط دسترسی runner به ۱۵ Secret لازم است؛ کلید را از لاگ استخراج نکنید.
۲. بعد از پایلوت موفق، برای اتصال سایت: نشانی REST وردپرس و Application Password حساب اختصاصی با حداقل مجوز لازم برای draft و media. رمز در Secret، نه فایل یا چت. ابتدا تست read-only، سپس یک draft آزمایشی با تأیید مالک.
۳. هاست فعلاً لازم نیست؛ اگر مسیر نهایی SFTP لازم شد، جداگانه و با دسترسی محدود گرفته شود. SQL مستقیم و FTP قدیمی به‌صورت پیش‌فرض فعال نشوند.
۴. انتشار عمومی، ترجمه‌ها، اعمال ادغام و تغییر workflow پیش‌فرض هر کدام تأیید مستقل و آزمون rollback می‌خواهند.
